# Electrical Output

Physical electrical output begins only after `RuntimeAuthority` creates an `AuthorizedActuation` token.

```text
ActuatorPairCommand
      |
      v
RuntimeAuthority
      |
      +-- denied ------> no token
      |
      +-- authorized --> AuthorizedActuation
                              |
                              v
                 ONE V2 electrical encoding
                              |
                              v
                 STM32F103 TIM3 / DIR owner
                              |
                              v
                        motor interface
```

No public electrical-output API accepts a raw `NormalizedCommand`.

## Reference assembly resources

The installed two-axis actuator mapping is:

| Robot role | PCB interface | PWM | Direction |
|---|---|---|---|
| Reaction wheel | BLDC_1 / M2 | PB1 / TIM3_CH4 | PB11 |
| Drive wheel | BLDC_2 / M1 | PA6 / TIM3_CH1 | PA4 |

BLDC_3 is not installed in the reference assembly and is outside the two-axis balance output owner.

The BLDC enable nets are hard-wired to 3.3 V on the reviewed board. Runtime authority therefore acts at PWM/direction ownership rather than through a software motor-enable GPIO.

## Vendor V2 electrical encoding

The V2.0 executable source configures TIM3 with `ARR=7199`, `PSC=0` at a 72 MHz timer clock, giving a 10 kHz PWM carrier.

For the two installed balance actuators the source uses:

```text
Drive / BLDC_2
    TIM3_CH1 on PA6
    DIR on PA4
    negative command -> DIR high
    PWM2, CCR1 = abs(command)

Reaction / BLDC_1
    TIM3_CH4 on PB1
    DIR on PB11
    negative command -> DIR high
    PWM1, CCR4 = 7200 - (abs(command) + 100)
```

At the physical PWM pin, the drive channel therefore represents increasing effort as an increasing **low-active** fraction. The canonical electrical encoder uses one common representation for both installed channels:

```text
m = abs(normalized_command)

DIR high            when command < 0
DIR low             otherwise
PWM line high       fraction = 1 - m
PWM line low        fraction = m
```

The STM32 adapter can therefore use ordinary TIM3 PWM mode 1 and write the complemented high fraction for both channels.

The vendor reaction-wheel `+100` timer-count term is not part of the canonical electrical mapping. Any dead zone, static friction, or minimum effective effort belongs in the actuator model and must be supported by measured or identified evidence.

## Ownership boundary

`swp-one-v2-electrical-output` owns the semantic-to-electrical encoding and accepts only `AuthorizedActuation`.

`swp-stm32f103-electrical-output` owns the concrete mutation boundary:

```text
TIM3_CH1  Drive PWM
TIM3_CH4  Reaction PWM
PA4       Drive DIR
PB11      Reaction DIR
```

Its constructor requires these exact HAL resource types. Other firmware code does not receive raw access through this interface.

TIM3/GPIO configuration remains the responsibility of the owning target firmware. The adapter does not silently claim or configure motor resources.

## Commissioning boundary

The current observation firmware and live-shadow firmware do not instantiate the electrical-output owner. Live-shadow continues to discard any `AuthorizedActuation` token generated by its synthetic profiling numerics.

Before the canonical runtime enables TIM3 motor channels on hardware, commissioning must establish at minimum:

```text
PWM pin idle waveform
PWM effort polarity
DIR-to-mechanical sign for both installed actuators
zero-command behavior
motor/ESC response around zero
safe behavior when a TIM3 channel is disabled
```

`disable_channels()` is therefore a timer-channel operation, not a claimed universal motor safe state.
